# Дизайн-система, соцдействия, дзен-режим, офлайн, редактор — дизайн

Дата: 2026-09-27. Продолжение `docs/plans/2026-09-26-song-editor-design.md`. Макеты утверждены в
визуальном компаньоне (`.superpowers/brainstorm/…/content/*.html`, не в git).

## Цель

Сделать приложение красивым и «живым» и добавить соцдействия:

- своя дизайн-система: тёмная тема «Неон тюнера» и светлая «Песенник», шум на фоне, анимации;
- страница «Песни»: наглядное добавление песни, красивый поиск и карточки без аккордов;
- страница трека: лайк, сохранить себе, просмотры, «Сыграл», кнопки «Послушать» и «Сыграть»,
  дзен-режим с автопрокруткой в темпе;
- вкладка «Моё»: сохранённые (офлайн в приложении), понравившиеся, мои разборы;
- редактор: песня в центре, данные и ритмы свёрнуты.

Решения пользователя: лайк и сохранение — разные действия; офлайн — только в Capacitor;
«Сыграл» — кнопка вручную + автоматически по окончании дзен-режима; просмотры — одно общее число,
не чаще раза в сутки от одного зрителя; числа — не больше 3 знаков (`999`, `1.2K`, `12K`, `2.5M`);
иконки вместо эмодзи; аккорды на карточках не показываем.

## Этапы

Одна спека, отдельные планы на этапы. Порядок: 1 → 2 → 3 → 4 → 5 → 6.

1. API: просмотры, лайки, сохранения, «Сыграл», библиотека.
2. Дизайн-система, темы, шум, базовые анимированные компоненты, оболочка (вкладки, шапка).
3. Страница «Песни».
4. Страница трека и дзен-режим.
5. «Моё» и офлайн-хранилище.
6. Редизайн редактора.

## 1. Данные и API

Таблицы (Drizzle, relations v2), миграция одна:

- `arrangement_view (arrangement_id, viewer_key text, day date)`, PK из трёх полей.
- `arrangement_like (user_id, arrangement_id, created_at)`, PK (user_id, arrangement_id).
- `arrangement_save (user_id, arrangement_id, created_at)`, PK (user_id, arrangement_id).
- `arrangement_play (user_id, arrangement_id, count int, last_played_at)`, PK (user_id, arrangement_id).
- В `arrangement`: `view_count`, `like_count`, `save_count` — `int not null default 0`. Меняются в той же
  транзакции, что и строка в таблице действия; списки не агрегируют.

Все внешние ключи — `on delete cascade`.

tRPC:

- `arrangements.view({ id, viewerKey })` — public. Вошедшему `viewerKey = user.id` (клиентское
  значение игнорируется), анониму — uuid устройства из localStorage (`chordtune.viewer`).
  `insert … on conflict do nothing`; если вставилось — `view_count + 1`. Возвращает `{ views }`.
- `arrangements.like / unlike({ id })`, `arrangements.save / unsave({ id })` — protected,
  идемпотентны: счётчик меняется, только если строка реально вставилась/удалилась. Возвращают
  `{ likes, liked }` / `{ saves, saved }`.
- `arrangements.played({ id, times = 1 })` — protected, `times` 1–50 (пачка из офлайн-очереди).
  Upsert `count + times`, `last_played_at = now()`. Возвращает `{ played }`.
- `byId` / `bySlug` дополнительно: `stats: { views, likes, saves }`, `me: { liked, saved, played } | null`.
- `library.saved()` — полные данные сохранённых разборов (как `byId`), новые сверху.
  `library.liked()`, `library.mine()` — элементы списка.
- Элемент списка (`songs.list`, `search.query`, `library.liked/mine`): `id, artist, artistSlug, title,
  songSlug, views, likes`; `chords` из выдачи убираются. `songs.list` сортирует по `view_count desc`,
  затем по `created_at desc` («Популярное»).
- Meili: документ `arrangements` получает `views`, `likes`; обновляется при сохранении разбора и
  при лайке/сохранении не чаще раза в 30 с на разбор (throttle в памяти процесса). Просмотры
  догоняются `search:reindex`.

Ошибки: действия без входа — `UNAUTHORIZED`; несуществующий разбор — `NOT_FOUND`.

Тесты (PGlite): повторный `view` в тот же день не считается, на следующий день — считается;
двойной `like` не меняет счётчик, `unlike` уменьшает; `save`/`unsave` аналогично; `played({times:3})`
добавляет 3; `library.saved` возвращает только свои сохранённые.

## 2. Дизайн-система

Семантические токены — CSS-переменные в `apps/web/src/app/globals.css`, компоненты используют
только их (через Tailwind-тему `--color-*`). Существующие shadcn-токены (`--background`,
`--primary`, …) переопределяются значениями наших тем, чтобы готовые компоненты перекрасились.

| Токен | Тёмная «Неон тюнера» | Светлая «Песенник» |
| --- | --- | --- |
| `--background` | `#0b0d17` + радиальный градиент `#1b2140` сверху | `#f6f1e7` |
| `--surface` / `--surface-2` | белый 4 % / 7 % | `#fffdf8` / `#f1e9da` |
| `--border` | белый 8 % | `#ece3d3` |
| `--foreground` / `--muted` | `#e6e9ff` / `#8a90b8` | `#1f1a14` / `#7a6f5e` |
| `--accent` / `--accent-foreground` | `#a3e635` / `#0b0d17` | `#1f1a14` / `#f6f1e7` |
| `--accent-2` (второй акцент) | `#6366f1` | `#c2410c` |
| `--chord` | `#67e8f9` | `#c2410c` |
| `--like` | `#fb7185` | `#c2410c` |
| `--saved` | `#bef264` | `#1f1a14` |
| `--glow` | `0 8px 22px rgb(163 230 53 / .3)` | `0 8px 20px rgb(31 26 20 / .25)` |
| `--noise-opacity` / `--noise-blend` | `.16` / `overlay` | `.28` / `multiply` |

- Ритмы: `--rhythm-1…8` (по ключу `A…P`) для обеих тем; `rhythm-colors.ts` переходит на них.
- Тюнер: `--tune-in/near/off` остаются, `--tune-in` = `--accent` в тёмной теме.
- Типографика: Geist Sans; в светлой теме заголовки страниц — засечки (`Iowan Old Style, Georgia,
  serif`) через токен `--font-display`; аккорды — Geist Mono.
- Радиусы: `--radius` 14 px, карточки 16–20 px, пилюли 999.
- Шум: слой `body::before` (`position: fixed`, `pointer-events: none`) с SVG `feTurbulence` в data-URI,
  прозрачность и blend из токенов.
- Темы: `next-themes`, `attribute="class"`, `defaultTheme="system"`, без вспышки; `<html>` больше не
  хардкодит `dark`. Выбор темы (Система / Тёмная / Светлая) — в поповере аккаунта; для гостя —
  там же, где кнопка «Войти» (иконка темы рядом).
- Движение: `apps/web/src/lib/motion.ts` — пружины `spring.soft` (stiffness 300, damping 30),
  `spring.pop` (500, 15), длительности. `motion` (уже в зависимостях) для layout-анимаций и
  `AnimatePresence`. При `prefers-reduced-motion` — только затухания.
- Компоненты uselayouts через `bunx shadcn add https://uselayouts.com/r/<name>`: `save-button`,
  `create-menu`, `discrete-tabs` (или свои по их мотивам, если не подходят к Base UI), перекрашенные
  в токены.
- Иконки — только `lucide-react`, без эмодзи.
- `formatCount(n)` в `apps/web/src/lib/format.ts`: `<1000` как есть; `<10K` — одна десятая без `.0`
  (`1.2K`); `<1M` — целые `K`; дальше `M` с одной десятой (`2.5M`). Округление вниз.

Оболочка:

- Мобильные: плавающая нижняя панель «Тюнер · Песни · Моё» с blur; активная плашка перетекает
  (`layoutId`). Десктоп: те же вкладки в шапке.
- Шапка: название, переключатель языка, аккаунт/тема.
- Переходы страниц: затухание + сдвиг 8 px (`template.tsx` в `[locale]`).

## 3. Страница «Песни»

- Заголовок, поле поиска (подсветка фокуса), debounce 200 мс.
- Карточка «Добавить песню» (лаймовая плашка); тап — пружинно раскрывает два пункта:
  «Написать» → `/songs/new`; «Вставить из заметки» → шторка с `textarea` и кнопкой «Вставить из
  буфера» (`navigator.clipboard.readText`, если доступно) → `importObsidian` → черновик в
  localStorage → `/songs/new`. Нераспознанная заметка — «Не похоже на заметку с аккордами» и кнопка
  «Открыть пустой редактор».
- Список: без запроса — «Популярное» (`songs.list`), с запросом — «Найдено» (`search.query`).
- Карточка: обложка-градиент (пара цветов по хешу имени исполнителя из палитры токенов), инициалы
  исполнителя, название, исполнитель, справа просмотры и лайки (`formatCount`, иконки `Eye`, `Heart`).
- Анимации: каскадное появление (задержка 45 мс на элемент), при фильтрации — `AnimatePresence` +
  `layout`.
- Состояния: скелетоны при загрузке; пусто — «Ничего не нашлось — добавь её первым» со ссылкой;
  поиск недоступен — тихая подсказка.

## 4. Страница трека и дзен-режим

- Шапка: «назад», меню ⋯ («Редактировать» — если автор, ведёт в редактор с `?edit=id`;
  «Скопировать ссылку»).
- Исполнитель, название (в светлой теме — засечками).
- Строка действий: `Eye` просмотры (не кнопка) | кнопки «Лайк» (`Heart`, число), «Сохранить»
  (`Bookmark`, число), «Сыграл» (`Guitar`, личное число). Анимации:
  - лайк: иконка сжимается и пружинит (`spring.pop`), 10 искр цветов `--like`, число перелистывается;
  - сохранить: закладка «падает», кольцо загрузки вокруг, тост «Сохранено · доступно офлайн»
    (в вебе — «Сохранено»);
  - сыграл: гриф качается, вылетает «+1»;
  - повторный тап снимает лайк/сохранение, число перелистывается обратно.
  - Capacitor: лёгкий haptic (`@capacitor/haptics`) на лайк и сохранение.
- При открытии — `arrangements.view` (один раз на монтирование).
- Ритмы и текст — как сейчас (`SongView`), в токенах.
- Нижний док (две компактные пилюли):
  - «Послушать» — подпись «Бой A · 90 BPM», во время игры — текущий раздел; проигрывает всю песню
    (`timeline` → `scheduleNotes`), повторный тап — стоп;
  - «Сыграть» — акцентная, подпись «Текст поедет сам», открывает дзен-режим.
- Дзен-режим — полноэкранный слой:
  - отсчёт 3-2-1 (700 мс на цифру);
  - строки как «аккорды над текстом», крупный шрифт; текущая строка яркая и чуть крупнее, пройденные
    гаснут; текущий аккорд подсвечен;
  - строка держится `Σ length` своих событий (в тактах × длительность такта из ритма и BPM), в
    последние 30 % плавно (smoothstep) подъезжает следующая; позиция строки — 34 % высоты экрана;
  - сверху: закрыть, название, текущий раздел, полоса прогресса; снизу: пауза/старт, индикатор
    долей, темп −/+ (шаг 5, 40–220), счётчик тактов;
  - тап по тексту — пауза; `navigator.wakeLock` на время режима (если есть);
  - строки без аккордов (текст, табы) показываются, но времени не занимают;
  - по окончании — карточка «+1» и `played` (офлайн — в очередь); выход раньше не засчитывается.
  - Расчёт — чистая функция `zenPosition(lines, t)` → `{ lineIndex, progress, chordIndex }` в
    `features/zen/zen-timing.ts` поверх `timeline` + `eventSeconds`.

## 5. «Моё» и офлайн

- Вкладка «Моё» (`/[locale]/library`): подвкладки «Сохранённые · Понравившиеся · Мои разборы»
  (скользящая плашка). Без входа — приглашение войти.
- Сохранённые — с меткой «офлайн» (в Capacitor).
- `features/library/offline-store.ts` на `idb`, база `chordtune`:
  - `songs`: id → `{ arrangement (как byId), savedAt }`;
  - `queue`: `{ id, type: 'played', arrangementId, times }`.
- Сохранить → запись в `songs` сразу; убрать → удаление.
- Страница трека в Capacitor (`/song?id=`): сначала локальная копия, затем тихое обновление с
  сервера (и перезапись локальной). Без сети — плашка «Офлайн» над текстом.
- «Сохранённые» строятся из `songs`; при сети сверяются с `library.saved()`: недостающие
  докачиваются, снятые на другом устройстве — удаляются.
- Без сети лайк/сохранение неактивны с подсказкой «Нужна сеть»; «Сыграл» уходит в `queue`.
- Очередь отправляется при старте, при событии `online` и `@capacitor/network`; одинаковые
  `arrangementId` сворачиваются в один `played({ times })`.
- Веб: хранилище работает так же, но без service worker страницы без сети не открываются
  (осознанно).

## 6. Редактор (вариант C)

- Шапка: «закрыть» (к списку или к треку) и анимированная «Сохранить» (idle → spinner → галочка).
- Карточка песни в одну строку: «Название · Исполнитель · Capo · BPM»; тап — шторка с полями
  (автокомплит исполнителя/названия, каподастр, BPM, тональность, заметки).
- Полоса чипов ритмов (`A ↓·↓↑·↑↓↑`) + «＋» с пресетами; тап по чипу — существующий
  `RhythmEditorSheet`.
- Холст — существующие визуальный/текстовый редакторы в токенах.
- Нижний док: «Визуально / Текст / Проверить»; «Проверить» — `SongView` в режиме чтения с
  «Послушать» и «Сыграть».
- Редактирование существующего разбора: `/songs/new?edit=id` (автор) — загрузка через `byId`,
  сохранение через `arrangements.update`.

## Ошибки

- Мутации оптимистичные: при ошибке откат, тост; `UNAUTHORIZED` — шторка входа.
- `wakeLock`/`clipboard`/haptics недоступны — функция просто без них.

## Тесты

- API на PGlite — см. раздел 1.
- `formatCount`: `0, 999, 1000→1K, 1234→1.2K, 9999→9.9K, 12345→12K, 999999→999K, 2_512_000→2.5M`.
- `zenPosition`: границы строк, `|` и повторы, строки без аккордов пропускаются, конец песни.
- Офлайн-очередь на `fake-indexeddb`: сворачивание `played`, удаление после успешной отправки,
  сохранение при ошибке сети.
- UI — проверка пользователем в браузере и на устройстве.
