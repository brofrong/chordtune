# Добавление песен: редактор аккордов, ритм, поиск — дизайн

Дата: 2026-09-26. Покрывает фазы 6–8 из `2026-09-26-chordtune-design.md` и добавляет ритм,
прослушивание и Meilisearch.

## Цель

Форма «Новая песня»: исполнитель с автокомплитом, название с автокомплитом, редактор
аккордов с двумя режимами (текст «аккорды над строкой» ↔ визуальный), ритм (бой/перебор)
с пресетами, своими паттернами и прослушиванием. Несколько песен из Obsidian-заметок
загружаются seed-скриптом.

## 1. Ритм и такты

**Паттерн** — один такт ритма на сетке. В песне хранится список паттернов, у каждого
короткий ключ (`A`, `B`, …) и название.

- **Бой** (`kind: 'strum'`): размер (`4/4`, `3/4`, `6/8`), сетка (8 или 16 клеток на
  такт 4/4), клетка — `D` ↓, `U` ↑, `d` ⇣ (глушёный вниз), `u` ⇡, `x` (удар с глушением),
  `-` пауза; флаг акцента. Шестёрка = `D - D U - U D U`.
- **Перебор** (`kind: 'pick'`): те же клетки, в клетке — набор струн: `B` (бас аккорда —
  струна тоники: Am → 5, G → 6, D → 4), `B'` (чередующийся бас), `1`–`6`. Несколько
  струн = щипок.
- **Пресеты**: четвёрка, шестёрка, восьмёрка, вальс (3/4), перебор «четвёрка»
  (Б-3-2-3), «восьмёрка» (Б-3-2-3-1-3-2-3), «тройка» (3/4), щипок. Любой пресет можно
  скопировать и изменить.

**Привязка к тексту.** `@A` — смена ритма, действует до следующей метки. Ставится в
заголовке раздела (`[Куплет] @B`) или перед любым аккордом. Без меток — паттерн `A`.

**Такты.** По умолчанию аккорд = такт. `|` в строке аккордов группирует:
`| Am G | F |` — Am и G по полтакта. Черты необязательны.

**Прослушивание.** ▶ в редакторе паттерна — паттерн по кругу на выбранном аккорде с BPM.
▶ на разделе — его аккорды по тактам с учётом меток.

**Отображение.** У заголовка раздела — полоска стрелок или мини-табулатура перебора.
В месте смены ритма над аккордом — цветной бейдж `B`, тап показывает паттерн.

## 2. Формат и `packages/chord-sheet`

Источник правды — текст:

```
[Куплет 1] @B
|${Am}Зачем кричать, ${G}когда никто не ${F}слышит|
|О чём мы ${Dm}говорим|
@A ${Am}...
```

Паттерны — отдельно, JSON-колонка `rhythms`:

```ts
type Rhythm = {
  key: string; // 'A'
  name: string;
  kind: 'strum' | 'pick';
  time: '4/4' | '3/4' | '6/8';
  grid: 8 | 16 | 6 | 12;
  steps: Step[];
};
type Step = { strum?: 'D' | 'U' | 'd' | 'u' | 'x'; strings?: ('B' | "B'" | 1 | 2 | 3 | 4 | 5 | 6)[]; accent?: boolean } | null;
```

API пакета (без зависимостей):

- `parse(source) → { doc, diagnostics }`, `serialize(doc)`. AST из основного дизайна плюс
  сегменты-метки `{ rhythm }` и `section.rhythm`. Парсер не бросает исключений.
- `parseChord('F#m7/C#') → { root, quality, bass }`; `H` → `B` (русская нотация).
- `toChordsOverLyrics(doc)` / `fromChordsOverLyrics(text)` — без потерь: позиция
  аккорда = колонка. Строка аккордов — все токены аккорды, `|` или `@X`.
- `importObsidian(md)` — `#Артист - Название`, блок ` ```chords `, строки
  `Паттерн:`/`Бой:`/`Перебор:`/`Каподастр:`/`BPM:`; стрелки → бой, «шестёрка»/«восьмёрка» →
  пресет, `Б-3-2-3` → перебор; нераспознанное — в заметку.
- `chordList(doc)` — уникальные аккорды; `timeline(doc, rhythms, bpm)` — лента
  `{ chord, rhythm, startBeat, beats, sectionIndex, lineIndex }` для плеера и будущего
  режима «следить за игрой».
- `presets`.

**Плеер** — `packages/audio/src/browser/strum-player.ts`: лента + аппликатуры →
расписание нот в `AudioContext` (Karplus–Strong из `guitar-synth`). Бой — проход по
струнам с разбросом 8–15 мс (вверх — обратный порядок), глушение — короткий шумный
удар. Перебор — отдельные ноты. Аппликатуры: `CHORD_CATALOG` + генерация баррэ E/A-формы
для остальных качеств.

## 3. Данные, API, поиск

Таблицы (Drizzle, relations v2):

- `artist` (id, name, slug unique, createdAt); уникальность `lower(name)`.
- `song` (id, artistId, title, slug, createdAt); unique (artistId, slug).
- `arrangement` (id, songId, authorId, content, rhythms jsonb, chords text[], key, capo,
  tempo, status `draft|published`, createdAt, updatedAt).

Поиск — **Meilisearch** (контейнер в `docker-compose`), Postgres — источник правды.

- Индекс `artists`: name, nameTranslit, songCount.
- Индекс `arrangements`: `searchableAttributes: [artist, artistTranslit, title,
  titleTranslit, lyrics]` (порядок = вес, текст песни — слабейший),
  `filterableAttributes: [artistId, chords]`.
- Транслит латиница ↔ кириллица, чтобы «лумен» находил LUMEN.
- Синхронизация: после коммита API пишет документ в Meili; ошибка логируется и не ломает
  сохранение. `bun run search:reindex` пересобирает индексы из Postgres.
- Вектора — позже через гибридный поиск Meili (embedder), без изменения API.

tRPC:

- `artists.search({ q })` — автокомплит, топ-8.
- `songs.searchByArtist({ artistId, q })`.
- `search.query({ q })` — общий поиск на странице «Песни».
- `arrangements.create({ artist: {id}|{name}, song: {id}|{title}, content, rhythms, capo,
  tempo, key })` — protected, недостающие artist/song создаются в той же транзакции.
- `arrangements.update`, `arrangements.byId` (правит только автор), `songs.list`.

Авторизация: минимальный sheet «Войти / Регистрация» (email + пароль, Better Auth).

Seed: `bun run db:seed` — пользователь `demo@chordtune.local` + 4 песни через
`importObsidian` из `apps/api/seed/`: Radiohead — Creep, Noize MC — Кошка,
Pixies — Where Is My Mind, LUMEN — Гореть.

## 4. Интерфейс

`/[locale]/songs/new`, мобильный в первую очередь.

```
┌──────────────────────────────────────┐
│ ← Новая песня             [Сохранить]│
│ Исполнитель [ нойз|              ]   │
│   Noize MC            12 песен       │
│   + Создать «нойз»                   │
│ Название    [ Кошка              ]   │
│ Каподастр [0▾]  BPM [90]  Тон. [Dm▾] │
├──────────────────────────────────────┤
│ Ритм                                 │
│ A Шестёрка   ↓·↓↑·↑↓↑        ▶  ✎    │
│ B Перебор    Б 3 2 3 1 3 2 3  ▶  ✎   │
│ [+ Паттерн]                          │
├──────────────────────────────────────┤
│ [ Текст | Визуальный ]  [Вставить из…]│
│ [Куплет 1] Ⓑ                    ▶    │
│ ┌Dm┐                ┌A#┐             │
│ Она сама по себе, она со всеми…      │
└──────────────────────────────────────┘
```

- Автокомплит: debounce 150 мс, клавиатура, последний пункт «+ Создать».
- Текстовый режим: моноширинный textarea; вставка Obsidian/UG разбирается
  `importObsidian` и заполняет форму.
- Визуальный режим: тап по букве → палитра аккордов (использованные + ввод);
  чипы перетаскиваются, долгий тап — удалить; ритм раздела — на заголовке; вставка `@`
  и `|` между чипами.
- Переключение режимов через AST; при ошибке парсинга — показать строку, не переключать.
- Редактор паттерна (sheet): пресет, размер, сетка, клетки (тап — цикл `↓ ↑ ⇣ ⇡ x ·`,
  двойной тап — акцент), для перебора — сетка струн; ▶ с аккордом и BPM.
- Страница песни (`/songs/[slug]`, `/song?id=`) — тот же рендер, read-only.

## 5. Ошибки и тесты

- Диагностики парсера: предупреждения (неизвестный аккорд) не мешают сохранению,
  ошибки (ссылка на несуществующий паттерн) — блокируют.
- Сервер повторно парсит контент, `rhythms` — Zod; контент ≤ 50 КБ, паттернов ≤ 16.
- Meili недоступен → автокомплит показывает «поиск недоступен», исполнителя можно
  ввести вручную (дедупликация по `lower(name)`).
- Черновик формы — в `localStorage`.

Тесты (`bun test`): round-trip парсера и конвертации на seed-песнях, `parseChord`,
`importObsidian` на реальных файлах, паттерны из стрелок и `Б-3-2-3`, лента с `|`/`@`;
генерация аппликатур для всех root × quality; расписание плеера; интеграционный тест
`arrangements.create`. UI — проверка в браузере.
